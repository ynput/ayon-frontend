# Representation traits

Shows the `traits` of a representation in the "Representation detail" dialog (`DetailsDialog`, Traits tab). The Raw tab keeps the old JSON view.

## Data

- `traits` comes from the representation REST entity: `{ "<trait id>": { ...trait data } }`, as written by `Representation.traits_as_dict()` in ayon-core.
- Trait definitions come from `GET /api/traits` (`useGetTraitDefinitionsQuery`, `shared/src/api/queries/traits`), mapped to `versioned id -> definition`. The backend merges the `server/traits.json` manifests of all installed addon versions, so old trait versions keep their definitions.
- No `variant` is passed on purpose: stored data may come from any installed addon version, not only the current bundle.
- A 404 means the server has no traits endpoint (older server). It is treated as "no definitions", not as an error.
- The definitions are refetched on `bundle` events, the same way as `listFrontendModules`.

## How a trait is shown

`resolveTraitRenderer` (`utils/traitModel.ts`) picks, in this order:
1. A dedicated widget from `registry.ts`, by the definition's `ui.widget`, or by versionless id when the widget lists the trait version (or lists none).
2. `SchemaTraitView`, when the exact trait version has a definition.
3. `GenericTraitTable` (raw values), with a "No definition" tag. The tooltip names the versions that do have a definition.

Definitions are data only. Never render HTML from them or load code they name.

## Schema contract

The schemas are generated by the exporter in ayon-core (`client/ayon_core/pipeline/traits/schema.py`). It only produces this subset of JSON Schema:
- Enums are stored and listed by member name.
- `Optional[X]` is `type: [X, "null"]`, or `anyOf` for complex types.
- Nested traits are `$ref: "#/$defs/<trait id>"`.
- `format` is `path`, `regex`, or `ayon-traits`. `ayon-traits` is an object of traits keyed by id, used for Bundle items.

Property order is the field order of the trait class, and the view keeps it.

The view checks each stored value against its schema without going into nested values (`matchesSchema`). Data that older ayon-core wrote differently is shown raw with a warning icon instead of failing. For example, it stored `"GapPolicy.forbidden"` instead of `"forbidden"`, and `FileLocations.v1` lists as Python repr strings.

## Tests

- `tests/unit/representationTraits.spec.ts` tests the pure modules in `utils/`. The components import `@ynput/ayon-react-components`, so unit tests can't render them.
- `tests/unit/support/traitFixtures.ts` holds real `traits_as_dict()` output and definitions from `/api/traits`. When trait classes change, regenerate it from ayon-core rather than editing it by hand.
